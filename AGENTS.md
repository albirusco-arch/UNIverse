# Universe — project notes

- Mobile app: Expo SDK 57 + Expo Router in `src/app/`; design tokens in `src/theme/tokens.ts`, shared UI in `src/components/ui/`, logo in `src/components/brand.tsx`.
- Brand: the name is written "UNIverse". Icons, splash, `assets/images/logo-mark.png` and `src/components/brand-assets.ts` are generated from `assets/brand/logo-original.png` by `npm run gen:brand`; never edit them by hand.
- The UI is English by default with Italian as second language: every user-facing string goes through `t()` from `src/i18n` and needs an entry in both `en.ts` and `it.ts` (add a `<key>_one` entry for singular forms). `src/i18n/i18n.test.ts` checks they match.
- Access: guests browse the catalogue and general university info (overview, quality, official-page clubs); posts, comments, equivalences, saving, ratings, groups and AI research need an account. Gate screens with `requireAccount()` and actions with `useRequireAccount()` (`src/components/account-gate.tsx`); the server enforces the same with RLS (anon policies) and 401s in edge functions, and demo mode mirrors it (`isDemoGuest`/`requireDemoStudent` in `src/data/api/core.ts`).
- Premium: `src/lib/premium.ts` (feature flags + entitlement stub). No payment provider yet; premium features stay "Coming soon".
- Sign-in is university email only: `src/lib/student-email.ts` in the app, the `auth.users` trigger in `supabase/migrations/20260926000000_core.sql` on the server.
- Data access lives only in `src/data/api/` (one file per area, re-exported from `index.ts`); every function supports Supabase and demo mode (no env vars). Demo data is in `src/data/demo/`.
- University catalogue: `src/data/universities.json` and `departments.json` are generated by `npm run import:universities` from `scripts/data/universities.curated.json` (Europe-first curated entries: type, departments, `verified`) plus the world list; run `npm run gen:seed` afterwards. Never add unverified courses, partnerships, rankings or fees to the catalogue.
- Backend: `supabase/migrations` (RLS on every table), `supabase/functions` (Deno; relative imports need `.ts`).
- AI agents: `supabase/functions/research` (course match, admission, scholarships, visa), `supabase/functions/university-insights` (ESG, teaching, clubs) and `supabase/functions/partner-lists` (reads a home university's official partner list), sharing `_shared/agent.ts`. Keep each `schema.ts` aligned with `src/data/types.ts`.
- Partner-first search: `departments`, `partnerships` and `courses` (migration `20260927000100_partnerships.sql`); ranking and filters in `src/lib/partner-search.ts`, subject areas as ISCED-F codes (`src/lib/isced.ts`), destination order Europe → Canada → Australia → others → US (`src/lib/destination-order.ts`). Never invent agreements: rows come from an admin import of an official list (`npm run import:partnerships`), the AI reading of the official list (unverified) or student suggestions with the official link (unverified).
- Opportunities (`src/app/(tabs)/opportunities.tsx`, table `opportunities`): internships, jobs and events linking to the original listing. LinkedIn, Handshake, JobTeaser and Eventbrite have no public API to read listings: never scrape or copy them; rows come from an admin import of listings we may republish (verified) or students sharing a link (unverified), and `src/lib/opportunities.ts` builds search links that open the same filters on each platform.
- Moments (`src/components/moments.tsx`, tables `moments`/`moment_reactions`, private storage bucket `moments`): club photos visible to students for 24 hours, one emoji reaction each, 10 a day per student; trending clubs in `src/lib/moments.ts`.
- Design is minimal: flat surfaces, no gradients or glow; the primary button is solid `colors.primary`.
- The UNIVERSE score lives in `src/lib/scores.ts` and the `university_scores` view; keep them in sync. Feed ranking: `src/lib/feed-ranking.ts`.
- SVG gradients and clip paths need per-instance ids (`useSvgId`), or they break on web when screens stack.
- Before finishing: `npm run typecheck && npm run lint && npm test`.

This is an Expo/React Native mobile application. Prioritize mobile-first patterns, performance, and cross-platform compatibility.

## Expo has changed — do not trust your training data

Expo ships breaking changes every SDK release. APIs you remember are likely renamed, moved, or removed. Before writing any code that touches an Expo, EAS, or React Native API:

1. Read the major version of the `expo` package in `package.json`.
2. Fetch the matching versioned docs: `https://docs.expo.dev/versions/v<major>.0.0/`
3. For anything else, fetch https://docs.expo.dev/llms.txt — an index of all Expo docs with corrections to common LLM misconceptions. Follow its links to the specific page you need; never answer from memory.

## Commands

Use `bunx` instead of `npx` if the project uses bun (`bun.lock` present).

```bash
npx expo install <package>  # ALWAYS use instead of npm/yarn/pnpm/bun add — resolves SDK-compatible versions
npx expo start              # start the dev server
npx expo lint               # lint
npx tsc --noEmit            # typecheck
npx expo-doctor             # diagnose dependency and config issues
npx expo install --fix      # fix incompatible package versions
```

Run lint and typecheck before declaring any task done.

## Navigation & Routing

- Use **Expo Router** for all navigation. Routes live in `src/app/` — every file there is a screen, `_layout.tsx` files define navigators. Keep non-route code (components, hooks, utils) outside `src/app/`.
- Import `Link`, `router`, and `useLocalSearchParams` from `expo-router`.
- Docs: https://docs.expo.dev/router/introduction.md

## Building with EAS

Use EAS to build, sign, and submit the app in the cloud (`eas build`, `eas submit`) and to ship over-the-air updates (`eas update`) — no local Xcode or Android Studio required. Run EAS CLI as `bunx eas-cli <command>` in Bun projects, or `npx eas-cli@latest <command>` otherwise; substitute that for bare `eas` in docs examples.
Docs: https://docs.expo.dev/eas/index.md

## Rules

- If `ios/` and `android/` directories do not exist, they are generated (Continuous Native Generation). Never create or edit them by hand — configure native behavior in `app.json` and config plugins.
- Expo Go only includes its bundled native modules. After adding a library with native code, the app needs a development build: `npx expo run:ios|android` locally, or `eas build --profile development`.
- Prefer recommended Expo modules over third-party libraries, and check your available skills before adding dependencies. Docs: https://docs.expo.dev/versions/latest/index.md
